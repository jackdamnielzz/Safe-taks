## 🎯 Overview

### Deployment Architecture

SafeWork Pro uses a modern serverless architecture:

- **Frontend**: Next.js 15 on Vercel Edge Network
- **Backend**: Firebase (Firestore, Auth, Storage, Functions)
- **CDN**: Vercel Edge Network (global distribution)
- **DNS**: Vercel DNS or custom domain provider

### Deployment Environments

| Environment | Purpose | URL | Branch |
|-------------|---------|-----|--------|
| **Local** | Development | http://localhost:3000 | Any |
| **Preview** | Feature testing | Auto-generated by Vercel | Feature branches |
| **Staging** | Pre-production testing | staging.safeworkpro.nl | `staging` |
| **Production** | Live application | safeworkpro.nl | `main` |

### Deployment Strategy

- **Continuous Deployment**: Automatic deployments on git push
- **Preview Deployments**: Every PR gets a unique preview URL
- **Zero-Downtime**: Vercel handles traffic switching
- **Instant Rollback**: One-click rollback to previous deployment

## 🔧 Environment Setup

### 1. Clone Repository

```bash
# Clone the repository
git clone git@github.com:jackdamnielzz/Safe-taks.git
cd Safe-taks

# Install dependencies
cd web
npm install

# Install Firebase Functions dependencies
cd ../functions
npm install
cd ..
```

### 2. Environment Variables

Create environment files for each environment:

#### Local Development (`.env.local`)

```bash
# Copy example file
cp web/.env.local.example web/.env.local

# Edit with your values
# web/.env.local
```

**Required Variables**:

```env
# Firebase Configuration
NEXT_PUBLIC_FIREBASE_API_KEY=your_api_key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your_project_id
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
NEXT_PUBLIC_FIREBASE_APP_ID=your_app_id
NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID=your_measurement_id

# Firebase Admin (Server-side)
FIREBASE_PROJECT_ID=your_project_id
FIREBASE_CLIENT_EMAIL=your_service_account@your_project.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"

# Stripe
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Stripe Product IDs
STRIPE_STARTER_PRICE_ID=price_...
STRIPE_PROFESSIONAL_PRICE_ID=price_...
STRIPE_ENTERPRISE_PRICE_ID=price_...

# Resend
RESEND_API_KEY=re_...
RESEND_FROM_EMAIL=noreply@safeworkpro.nl

# OpenWeather
OPENWEATHER_API_KEY=your_openweather_key

# Application
NEXT_PUBLIC_APP_URL=http://localhost:3000
NODE_ENV=development
```

#### Staging (Vercel Environment Variables)

Set in Vercel Dashboard → Project → Settings → Environment Variables:

- Environment: **Preview** and **Development**
- Same variables as local, but with staging values

#### Production (Vercel Environment Variables)

Set in Vercel Dashboard → Project → Settings → Environment Variables:

- Environment: **Production**
- Same variables as local, but with production values
- Use production API keys (Stripe live keys, etc.)

### 3. Firebase Setup

#### Initialize Firebase

```bash
# Login to Firebase
firebase login

# Select your project
firebase use your_project_id

# Deploy Firestore rules
firebase deploy --only firestore:rules

# Deploy Firestore indexes
firebase deploy --only firestore:indexes

# Deploy Storage rules
firebase deploy --only storage

# Deploy Functions
cd functions
npm run build
firebase deploy --only functions
```

#### Firestore Security Rules

Verify rules are deployed:

```bash
# View current rules
firebase firestore:rules:get

# Test rules locally
firebase emulators:start --only firestore
```

#### Create Firebase Service Account

1. Go to Firebase Console → Project Settings → Service Accounts
2. Click "Generate New Private Key"
3. Save the JSON file securely
4. Extract values for environment variables:
   - `FIREBASE_PROJECT_ID`: From JSON `project_id`
   - `FIREBASE_CLIENT_EMAIL`: From JSON `client_email`
   - `FIREBASE_PRIVATE_KEY`: From JSON `private_key` (keep \n characters)

### 4. Stripe Setup

#### Create Products and Prices

```bash
# Login to Stripe Dashboard
# https://dashboard.stripe.com

# Create products:
# 1. Starter Plan - €49/month
# 2. Professional Plan - €149/month
# 3. Enterprise Plan - €499/month

# Copy Price IDs to environment variables
```

#### Setup Webhook

1. Go to Stripe Dashboard → Developers → Webhooks
2. Add endpoint: `https://your-domain.com/api/stripe/webhook`
3. Select events:
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.payment_succeeded`
   - `invoice.payment_failed`
4. Copy webhook secret to `STRIPE_WEBHOOK_SECRET`

### 5. Resend Setup

#### Create Account and Verify Domain

```bash

#    - CNAME records for email sending

```

#### Test Email Sending

```bash
  -H "Content-Type: application/json" \
  -d '{"to":"your-email@example.com"}'
```

```bash

cd web

npm run dev
```

### Automatic Deployment

Production deploys automatically when you push to `main`:

1. **Push to main** → Triggers Vercel build
2. **Build completes** → Vercel runs tests
3. **Tests pass** → Vercel deploys to production
4. **Deployment live** → Traffic switches to new version
5. **Old version** → Kept for instant rollback

## 🔄 Rollback Procedures

### Instant Rollback (Vercel)

#### Via Vercel Dashboard

1. Go to https://vercel.com/your-team/safe-taks
2. Click "Deployments"
3. Find previous successful deployment
4. Click "..." menu → "Promote to Production"
5. Confirm rollback

#### Via Vercel CLI

```bash
# List recent deployments
vercel ls

# Rollback to specific deployment
vercel rollback [deployment-url]

# Or rollback to previous deployment
vercel rollback
```

### Firebase Rollback

#### Firestore Rules

```bash
# List rule versions
firebase firestore:rules:list

# Rollback to specific version
firebase firestore:rules:release [version-id]
```

#### Functions

```bash
# List function versions
firebase functions:list

# Rollback specific function
firebase functions:delete [function-name]
firebase deploy --only functions:[function-name]
```

### Database Rollback

**⚠️ WARNING**: Database rollbacks are complex and risky.

#### Firestore Backup Restore

```bash
# List backups
firebase firestore:backups:list

# Restore from backup
firebase firestore:backups:restore [backup-id]
```

#### Manual Data Restore

1. Export current data (backup)
2. Restore from previous backup
3. Verify data integrity
4. Test application thoroughly

### Rollback Decision Matrix

| Issue | Severity | Action | Rollback? |
|-------|----------|--------|-----------|
| Minor UI bug | Low | Fix forward | No |
| Performance degradation | Medium | Investigate, may rollback | Maybe |
| Authentication broken | High | Immediate rollback | Yes |
| Data corruption | Critical | Immediate rollback + restore | Yes |
| Payment processing broken | Critical | Immediate rollback | Yes |

## 🔧 Troubleshooting

### Common Issues

#### 1. Build Failures

**Symptom**: Vercel build fails

**Causes**:
- TypeScript errors
- Missing dependencies
- Environment variables not set

**Solutions**:
```bash
# Check build locally
npm run build

# Fix TypeScript errors
npm run type-check

# Install missing dependencies
npm install

# Verify environment variables in Vercel dashboard
```

#### 2. Firebase Connection Errors

**Symptom**: "Firebase: Error (auth/configuration-not-found)"

**Causes**:
- Missing Firebase config
- Incorrect environment variables
- Firebase project not initialized

**Solutions**:
```bash
# Verify Firebase config
cat web/.env.local | grep FIREBASE

# Re-initialize Firebase
firebase use your_project_id

# Check Firebase console for project status
```

#### 3. Stripe Webhook Failures

**Symptom**: Payments not processing, webhook errors in Stripe dashboard

**Causes**:
- Incorrect webhook URL
- Wrong webhook secret
- Webhook endpoint not deployed

**Solutions**:
```bash
# Verify webhook URL in Stripe dashboard
# Should be: https://your-domain.com/api/stripe/webhook

# Test webhook locally with Stripe CLI
stripe listen --forward-to localhost:3000/api/stripe/webhook

# Check webhook secret matches environment variable
```

#### 4. Email Sending Failures

**Symptom**: Emails not being sent

**Causes**:
- Resend API key invalid
- Domain not verified
- Rate limit exceeded

**Solutions**:
```bash
# Verify Resend API key
curl https://api.resend.com/emails \
  -H "Authorization: Bearer $RESEND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from":"noreply@safeworkpro.nl","to":"test@example.com","subject":"Test","html":"Test"}'

# Check domain verification in Resend dashboard
# Check rate limits and usage
```

#### 5. Performance Issues

**Symptom**: Slow page loads, high response times

**Causes**:
- Large bundle size
- Unoptimized images
- Slow database queries
- No caching

**Solutions**:
```bash
# Analyze bundle size
npm run analyze

# Optimize images
# Use next/image component
# Enable image optimization in next.config.ts

# Add caching headers
# Implement Redis caching (Upstash)

# Optimize database queries
# Add indexes in Firestore
# Use pagination
```

## 🔄 CI/CD Pipeline

### GitHub Actions Workflow

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to Vercel

on:
  push:
    branches: [main, staging]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: cd web && npm ci
      - run: cd web && npm test
      - run: cd web && npm run type-check
      - run: cd web && npm run lint

  deploy:
    needs: test
    runs-on: ubuntu-latest
    if: github.event_name == 'push'
    steps:
      - uses: actions/checkout@v3
      - uses: amondnet/vercel-action@v20
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID}}
          vercel-args: ${{ github.ref == 'refs/heads/main' && '--prod' || '' }}
```

### Pipeline Stages

1. **Lint**: Check code style
2. **Type Check**: Verify TypeScript
3. **Test**: Run unit and integration tests
4. **Build**: Build Next.js application
5. **Deploy**: Deploy to Vercel
6. **Verify**: Run smoke tests

### Required Secrets

Add to GitHub repository secrets:

- `VERCEL_TOKEN`: Vercel API token
- `VERCEL_ORG_ID`: Vercel organization ID
- `VERCEL_PROJECT_ID`: Vercel project ID

### Branch Protection Rules

Configure in GitHub repository settings:

- **main branch**:
  - Require pull request reviews (1 approval)
  - Require status checks to pass
  - Require branches to be up to date
  - Include administrators

- **staging branch**:
  - Require status checks to pass
  - Allow force pushes (for testing)
