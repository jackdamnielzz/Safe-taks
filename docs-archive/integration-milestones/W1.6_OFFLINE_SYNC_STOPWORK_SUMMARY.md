## 📊 Architecture Decisions

### 1. Extend Existing vs Create New
**Decision**: Extended existing `offlineSyncManager.ts`
**Rationale**: 
- Reuse 600+ lines of tested code
- Consistent offline strategy across app
- Single sync service for all entities
- Reduced maintenance burden

### 2. localStorage Fallback
**Decision**: Use localStorage for stop-work queue
**Rationale**:
- Simpler implementation for MVP
- Sufficient for stop-work alerts (low volume)
- Can migrate to IndexedDB later if needed
- Immediate availability

### 3. Priority Queue
**Decision**: Added priority field to LMRA sessions
**Rationale**:
- Stop-work alerts need critical priority
- Future-proof for other priority levels
- Minimal schema change
