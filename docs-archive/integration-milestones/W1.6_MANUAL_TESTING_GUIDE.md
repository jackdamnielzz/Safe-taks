## End-to-End Testing Flow

### Test Scenario 1: Complete LMRA Wizard with Stop-Work Alert

**Objective**: Verify the complete flow from LMRA creation to stop-work alert submission.

#### Steps:

1. **Start the dev server**:
   ```bash
   cd web
   npm run dev
   ```

2. **Open browser**:
   - Navigate to `http://localhost:3000` (or 3001 if redirected)
   - Open DevTools (F12) to monitor console and network

3. **Navigate to LMRA Wizard**:
   - Click on "New LMRA" or navigate to `/lmra/new`
   - You should see the LMRA wizard interface

4. **Fill out LMRA form** (Step-by-step):
   - **Step 1 - TRA Selection**: Select a TRA template
   - **Step 2 - Location**: Enter location details
   - **Step 3 - Weather**: Verify weather conditions (if API configured)
   - **Step 4 - Team**: Add team members
   - **Step 5 - Equipment**: Verify equipment
   - **Step 6 - Hazards**: Identify hazards
   - **Step 7 - Go/No-Go**: Make decision
   - **Step 8 - Signatures**: Collect signatures

5. **Verify Stop-Work Button appears**:
   - After LMRA is created (has an ID), check bottom-right corner
   - Red "STOP WERK" button should be visible
   - Button should have fixed position (z-index: 50)

6. **Click Stop-Work Button**:
   - Click the red button
   - Dialog should open with 4-step process

7. **Complete Stop-Work Alert** (4 steps):
   
   **Step 1 - Details**:
   - Enter reason (max 100 characters): "Onveilige situatie gedetecteerd"
   - Select severity: High
   - Select category: Hazard
   - Enter description (max 500 characters): "Gevaarlijke situatie met potentieel voor letsel"
   - Click "Volgende"

   **Step 2 - Photos** (Optional):
   - Click "Foto toevoegen" to capture/upload photos
   - Or skip by clicking "Volgende"

   **Step 3 - Signature**:
   - Draw signature on canvas
   - Verify signer name shows real user name (from auth context)
   - Verify role shows correct role
   - Click "Bevestigen"

   **Step 4 - Confirmation**:
   - Review all entered information
   - Click "Bevestig Stop-Werk"

8. **Verify Alert Creation**:
   - Check console for "Stop-work alert created:" message
   - Verify success notification appears
   - Dialog should close automatically

9. **Verify LMRA Status Update**:
   - LMRA status should update to "stop_work"
   - UI should reflect the stopped status

#### Expected Results:

✅ Stop-work button visible after LMRA creation  
✅ Dialog opens with 4-step process  
✅ Form validation works (required fields)  
✅ Real user data captured (name, role)  
✅ Alert created successfully  
✅ LMRA status updated to "stop_work"  
✅ No console errors

## Offline Sync Testing

### Test Scenario 2: Create Alert While Offline

**Objective**: Verify offline queue functionality and auto-sync on reconnection.

#### Steps:

1. **Start dev server and open browser** (as above)

2. **Open DevTools Network Tab**:
   - Press F12 → Network tab
   - Enable "Offline" mode (throttling dropdown)

3. **Create LMRA** (while online):
   - Complete LMRA wizard as in Test Scenario 1
   - Verify LMRA is created successfully

4. **Enable Offline Mode**:
   - In DevTools Network tab, select "Offline"
   - Verify network indicator shows offline status

5. **Create Stop-Work Alert** (while offline):
   - Click Stop-Work button
   - Fill out all 4 steps
   - Click "Bevestig Stop-Werk"

6. **Verify Offline Behavior**:
   - Check for message: "Melding wordt verzonden zodra u online bent"
   - Alert should be queued in localStorage
   - No network errors should appear

7. **Inspect localStorage**:
   - In DevTools → Application → Local Storage
   - Look for `stopWorkQueue` key
   - Verify alert is stored with pending status

8. **Go Back Online**:
   - In DevTools Network tab, select "No throttling"
   - Wait for auto-sync (should trigger within 5 seconds)

9. **Verify Auto-Sync**:
   - Check console for "Syncing pending stop-work alerts" message
   - Verify network request to `/api/lmras/{lmraId}/stop-work`
   - Alert should be removed from localStorage queue
   - Success notification should appear

10. **Verify Alert in Database**:
    - Use API to list alerts: `GET /api/stop-work`
    - Verify alert appears in response

#### Expected Results:

✅ Alert queued when offline  
✅ Offline message displayed  
✅ Alert stored in localStorage  
✅ Auto-sync triggered on reconnection  
✅ Alert successfully created in database  
✅ Queue cleared after successful sync  
✅ No data loss

## Stop-Work Alert Testing

### Test Scenario 3: Supervisor Acknowledgment & Resolution

**Objective**: Verify supervisor can acknowledge and resolve stop-work alerts.

#### Steps:

1. **Create a stop-work alert** (as field worker):
   - Follow Test Scenario 1 to create an alert
   - Note the alert ID from console or response

2. **Switch to supervisor account**:
   - Log out current user
   - Log in as supervisor (role: supervisor or safety_manager)

3. **View stop-work alerts**:
   - Navigate to stop-work alerts list
   - Verify alert appears with "active" status

4. **Acknowledge alert**:
   - Click "Acknowledge" button
   - Verify status changes to "acknowledged"
   - Verify acknowledgedBy and acknowledgedAt fields populated

5. **Resolve alert**:
   - Enter resolution notes
   - Click "Resolve" button
   - Verify status changes to "resolved"
   - Verify resolvedBy and resolvedAt fields populated

6. **Verify LMRA status**:
   - Navigate back to LMRA
   - Verify LMRA can be resumed or marked complete

#### Expected Results:

✅ Supervisor can view all alerts  
✅ Acknowledgment updates status correctly  
✅ Resolution requires notes  
✅ All audit fields populated  
✅ LMRA status reflects resolution

## Troubleshooting

### Common Issues and Solutions

#### Issue 1: Dev Server Won't Start

**Symptoms**: Port already in use, compilation errors

**Solutions**:
```bash
# Kill process on port 3000
npx kill-port 3000

# Clear Next.js cache
rm -rf web/.next

# Reinstall dependencies
cd web
rm -rf node_modules package-lock.json
npm install

# Try different port
npm run dev -- -p 3001
```

#### Issue 2: Stop-Work Button Not Visible

**Symptoms**: Button doesn't appear after LMRA creation

**Checks**:
- Verify LMRA has an ID (check state in React DevTools)
- Check console for errors
- Verify [`LMRAWizard.tsx`](web/src/components/lmra/LMRAWizard.tsx:1) includes StopWorkButton
- Check CSS z-index conflicts

**Solution**:
```typescript
// In LMRAWizard.tsx, verify this code exists:
{state.lmra.id && (
  <div className="fixed bottom-4 right-4 z-50">
    <StopWorkButton
      lmraId={state.lmra.id as string}
      onStopWork={handleStopWorkCreated}
    />
  </div>
)}
```

#### Issue 3: Offline Sync Not Working

**Symptoms**: Alerts not syncing when back online

**Checks**:
- Verify IndexedDB is enabled in browser
- Check localStorage for `stopWorkQueue`
- Verify network listener is registered
- Check console for sync errors

**Debug Steps**:
```javascript
// In browser console:
// Check localStorage
console.log(localStorage.getItem('stopWorkQueue'));

// Check IndexedDB
indexedDB.databases().then(console.log);

// Manually trigger sync
window.dispatchEvent(new Event('online'));
```

#### Issue 4: API Returns 404 LMRA Not Found

**Symptoms**: POST to stop-work returns 404

**Checks**:
- Verify LMRA exists in database
- Check orgId matches between LMRA and request
- Verify auth context provides correct orgId

**Solution**:
```bash
# Seed LMRA first
curl -X POST http://localhost:3000/api/dev/seed-lmra \
  -H "Content-Type: application/json" \
  -d '{"id":"test-lmra-001","orgId":"test-org"}'

# Then create alert
curl -X POST http://localhost:3000/api/lmras/test-lmra-001/stop-work \
  -H "Content-Type: application/json" \
  -d '{ ... }'
```

#### Issue 5: Tests Failing

**Symptoms**: Jest tests fail with module errors

**Solutions**:
```bash
# Clear Jest cache
npm test -- --clearCache

# Update snapshots
npm run test:update-snapshots

# Run specific test file
npm test stopWorkService

# Check test configuration
cat web/jest.config.js
```
